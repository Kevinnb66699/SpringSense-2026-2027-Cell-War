# AI 设计：确定性重放 + 蒙特卡洛模拟打分

> 2026-08-25 团队定案的路线（备选的 alpha-beta+神经网络路线为何不选，见当时群里讨论：
> 随机节点多、多人顺序行动、每回合由一串微决策组成，alpha-beta 的剪枝在这里剪不动）。
> 本文描述已落地的 demo 实现与调参入口。

## 1. 原理

引擎是确定性的（同种子 + 同答案序列 = 完全相同的对局），这本身就是一台完美的模拟器。
MC 搜索桥利用这一点，在每个决策点上"开平行世界试错"：

```
每名玩家回合开始 ──→ 拍局面快照（CWSnapshot.capture），此后记录所有答案（线格式）
面对一个决策请求 ──→ 对每个候选答案：
                       还原快照 → 回放答案序列 → 注入该候选 → 给克隆局的 rng 重播种
                       → 用启发式策略把所有人代打 horizon 个世界回合 → 评分
                     取 K 局平均分最高的候选作答
```

- 回放段与真实对局逐位一致（rng 状态在快照里，答案逐条回放）；
- 重播种发生在候选被消耗的那一刻，让每次推演的"未来骰运"各不相同；
- 候选间共用同一组推演种子（配对比较），分差只来自候选本身，压低小样本方差；
- 启发式会选的候选有先验加成（`prior_bonus`）：分差明显超过噪声才推翻启发式。

## 2. 组件

| 组件 | 位置 | 职责 |
|---|---|---|
| CWSnapshot | core/cw_snapshot.gd | 全部规则状态的拍照/还原（含 rng seed+state）|
| CWGame.resume_game | core/cw_game.gd | 从回合中断点续跑；`max_rounds` 为推演视界 |
| CWBridge.on_turn_start | core/cw_bridge.gd | 回合起点钩子（MC 取快照；将来联机比对哈希）|
| MCBridge | ui/mc_bridge.gd | 第 5 座桥：搜索决策 + 答案记录 + 评分 |
| MCBridge.ReplayBridge | 同上（内部类） | 克隆局的回放/代打桥 |
| 快照等价性测试 | tests/headless_test.gd `_test_snapshot` | 快照+回放终局哈希必须与原局一致（CI）|
| 胜率基准 | tests/mc_benchmark.gd | 手动跑，对比启发式基线（不进 CI）|

## 3. 确定性红线（违反 = 联机与测试全崩）

1. 推演只发生在**克隆局**上；真实对局的 `game.rng` 绝不因搜索被额外消耗或重播种。
2. 桥侧随机（选种子、启发式的随机决策）用桥自己的 `rng`，与引擎无关。
3. **引擎新增影响规则的状态时，`CWGame.state_hash()` 和 `CWSnapshot` 两处都要加**；
   漏加的症状是克隆局分叉，由 CI 的快照等价性测试与 `validate_replay` 自检兜底。

## 4. 参数旋钮（MCBridge 成员变量）

| 旋钮 | 默认 | 含义 |
|---|---|---|
| mc_faction | "" | 哪个阵营用 MC（"" = 所有非人类阵营）|
| playouts (K) | 10 | 每个候选的推演局数：难度/耗时旋钮 |
| horizon | 4 | 每次推演最多再跑几个世界回合 |
| max_candidates | 8 | 选格/选边类请求的候选裁剪上限 |
| prior_bonus | 8.0 | 启发式先验加成（0 = 纯推演分数）|
| validate_replay | false | 回放对齐自检（约慢 10 倍，排查快照 bug 时开）|
| debug_progress | false | 打印与启发式产生分歧的决策及分数 |

## 5. 基准结果（2026-08-25，4 人局 12 种子，K=10 视界=4）

| 配置 | 胜率 |
|---|---|
| 基线：双方启发式 | 癌症 3/12（免疫 9/12）|
| MC 癌症 vs 启发式免疫 | 癌症 3/12（追平，不再像早期版本那样自残）|
| **MC 免疫 vs 启发式癌症** | **免疫 11/12（基线 9/12，可见提升）** |

耗时：无头 ~9 s/整局；UI 里单个决策通常 <0.5 s。回放对齐自检：数万次推演 0 失配。

```bash
# 复现基准（在仓库根目录）
<godot> --headless --path game -s tests/mc_benchmark.gd
```

## 6. 已知局限与后续方向

- **单步推演的结构性限制**：候选之后的走法全由启发式代打，"需要连续配合才兑现的妙手"
  推演不出来——这是癌症侧只能追平启发式的主因。免疫的走位收益单步就能兑现，故有提升。
- 后续升级路径（对应当时讨论的第 2 阶段）：
  1. **学习评分函数**：自博弈日志导出特征+终局结果 → Python 训练小型 MLP →
     权重存 JSON → GDScript 手写两层矩阵乘推理（不引插件）；替换 `MCBridge._eval`。
  2. **演化调参**：GA/CMA-ES 离线调启发式与评分权重，自博弈胜率当适应度
     ——顺带解决 11:1 阵营失衡的数值问题。
  3. 更深的搜索结构（每回合多步联合候选、UCB 分配推演预算）视需求再议。
- 快照模块是通用基建：**存档/读档**与**联机断线恢复**将来直接复用 CWSnapshot。
