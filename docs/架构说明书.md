## 1. 项目是什么

《Cell War》：免疫细胞 vs 癌细胞的六边形棋盘对抗桌游（ver.0.98）的电子化版本。

- 引擎：**Godot 4.5 stable**（标准版，非 .NET），语言：**GDScript**
- 棋盘：半径 4 的正六边形蜂窝，共 **61 格**，轴向坐标 `Vector2i(q, r)`
- 对局：4 人或 6 人，20 个世界回合；已实现模式：人机对战 / 本地热座 / AI 观战演示
- 渲染：`gl_compatibility`；窗口 1600×900，`canvas_items` + `expand` 整体缩放

## 3. 总体架构：三条铁律

整个项目的架构可以压缩成三句话，**违反任何一条的代码不允许合入**：

1. **`scripts/core/` 是纯逻辑**——不 `extends Node`、不读输入、不碰场景树、不 print（用
   `log_line`）。它必须能在无头（headless）环境下瞬时跑完整局（测试和将来的联机重放都靠这一点）。
2. **一切玩家决策走「问答桥」**——引擎需要任何人（或 AI）做选择时，只能
   `await game.ask_option / ask_hex / ask_edge`，由桥返回答案。引擎不知道答案来自点击、AI 还是网络。
3. **一切游戏随机走 `game.rng`**——掷骰、洗牌、事件抽取全部出自这一个带种子的 RNG。
   同种子 + 同答案序列 = 逐位相同的对局（确定性，联机锁步与回放的根基，有测试守护）。

## 4. 问答桥（核心模式，必须理解）

```
┌──────────────┐  ask(req) / show_roll   ┌──────────┐   点击/策略/网络
│ 规则引擎 core │ ──────────────────────→ │  Bridge   │ ←──────────────  玩家
│  (await 挂起) │ ←────────────────────── │ (4 种实现) │
└──────────────┘        返回答案           └──────────┘
```

请求 `req` 是 Dictionary，完整格式见 `cw_bridge.gd` 文件头注释。要点：

- `type`：`pick_option`（选项）/ `pick_hex`（选格子）/ `pick_edge`（选边）
- `owner_id` / `owner_faction`：决策归属（机器可读，AI 路由与将来联机靠它）；`who` 仅是显示名
- 部分请求带 `tag`（`setup_pos` / `move_step` / `attack_target`）和 `actor`（决策者 CWPlayer），
  供启发式 AI 识别场景
- 答案：`values`/`options` 中的一个元素；取消返回 `null`

五种桥（都继承 `CWBridge`）：

| 桥 | 文件 | 行为 |
|---|---|---|
| CWBridge（基类） | core/cw_bridge.gd | 自动选第一项（无头测试兜底）；带答案线格式 codec 与 on_turn_start 钩子 |
| UIBridge | ui/ui_bridge.gd | 转交界面，await 玩家点击 |
| DemoBridge | ui/demo_bridge.gd | 随机作答（观战演示 / 冒烟测试） |
| HybridBridge | ui/hybrid_bridge.gd | 人类阵营走 UI，AI 阵营走启发式策略（人机对战） |
| MCBridge | ui/mc_bridge.gd | 蒙特卡洛推演搜索（快照→回放→推演→评分，见 `docs/AI设计.md`） |

**将来的 NetBridge（联机）是第 6 种桥，引擎零改动**——这是本架构最重要的扩展点，别破坏它。

## 5. core 模块地图（改什么去哪个文件）

`cw_game.gd` 持有**全部对局状态**与通用工具，流程委托给 7 个功能模块。模块自身**无状态**，
只持 `var game: CWGame` 引用互相调用（如 `game.combat.attack_check(p)`）。

| 文件 | 职责 | 典型修改 |
|---|---|---|
| hexlib.gd | 六边形数学（坐标/距离/边/角点），静态函数库 | 几乎不需要动 |
| cw_data.gd | **全部数值与文案表**：常量、官方布局、卡牌×56、事件×27、进化×12 | 调数值、改文案、加卡/事件/进化的"定义" |
| cw_board.gd | 棋盘状态：组织/固化/特殊事件/墙壁 + 相关查询 | 新地形类、新棋盘查询 |
| cw_player.gd | 单个细胞的状态与属性计算（攻击力/范围等） | 新玩家状态标记 |
| cw_deck.gd | 牌库：抽牌/弃牌/洗回（用 game.rng） | 一般不动 |
| cw_bridge.gd | 桥基类 + req 格式文档 + 答案线格式 codec | 新请求类型（先讨论！） |
| cw_game.gd | 状态 + 工具（ask_*/d6/查询）+ 主循环 + 胜负 + state_hash | 新全局状态（记得进 state_hash 和 dispose 语义） |
| cw_setup.gd | 布置阶段 | 开局规则 |
| cw_world.gd | 世界回合开始（清标记/固化衰减/进化时机/事件触发时机） | 回合节奏 |
| cw_events.gd | 27 个世界事件的**效果实现** | 改某个事件的效果 |
| cw_turn.gd | 玩家回合时序（复活/血管/卡池/工厂/自由抽卡/特殊行动/回合末结算） | 回合内流程 |
| cw_movement.gd | 移动阶段（掷骰步数/逐步移动/移动联动） | 移动规则 |
| cw_combat.gd | 攻击三档判定/击退/双重打击/击杀 | 战斗规则 |
| cw_cards.gd | 抽卡入口 + 28 种卡牌的**效果实现** | 改某张卡的效果 |
| cw_snapshot.gd | 对局状态快照/还原（MC 推演克隆；将来存档/断线恢复） | **新增规则状态时与 state_hash 一起同步** |

ui/ 一览：`main.gd`（顶层组装 + 问答桥接线 + 对局流程）、`side_panel.gd`（侧边面板填内容）、
`menu_screen.gd`（主菜单按钮接线）、`pause_menu.gd`（Esc 暂停菜单：树暂停 + 放弃对局）、
`board_view.gd`（棋盘绘制与点击拾取）、`dice_overlay.gd`（掷骰动画）、四座 UI 侧桥。
注意：桥里创建延迟计时器一律 `tree.create_timer(t, false)`（process_always=false），
否则 Esc 暂停冻结不了 AI 流程。

**UI 布局与逻辑的分工**（2026-08-25 场景化改造后）：
- **静态布局**（面板结构、按钮、间距、字体、配色）在 `scenes/*.tscn` 与 `scenes/ui_theme.tres`，
  **在 Godot 编辑器里可视化修改**，改完不需要动脚本；脚本用 `%节点名`（场景唯一名）取节点，
  编辑器里移动/重排节点不影响脚本，但**改节点名前先搜对应脚本**。
- **动态内容**（选项按钮、日志行、玩家列表 BBCode）仍由脚本运行时生成——数量与文案由引擎决定，没法在编辑器里摆。
- **程序化绘制**（棋盘 61 格、骰子动画）永远在代码里（`board_view.gd` / `dice_overlay.gd` 的 `_draw`），
  编辑器帮不上忙。
- 桥 → 界面只有三个入口：`main.show_request(req)` / `main.clear_request()` / `main.play_dice(...)`，
  签名不可改（将来 NetBridge 也走这套）。
- `.tscn` / `.tres` 合并冲突很难手解，**同一场景文件同一时间只由一人修改**，改前群里说一声。

## 6. 状态归属与生命周期

- 对局状态**只**存在于 CWGame / CWBoard / CWPlayer / CWDeck。功能模块、桥、UI 均不得私藏规则状态。
- UI 是纯"读者"：`_process` 里读 `game.*` 渲染；写入只能通过 `bridge.answer(...)` 回答请求。
- `game ↔ 模块/桥` 是循环强引用：**丢弃一个已结束的对局前必须调 `game.dispose()`**
  （GDScript 引用计数不回收环）。tests 与 `main._start` 已接好，新增对局创建点照做。
- **新增影响规则的状态字段时，三处同步**：`CWGame.state_hash()`、`CWSnapshot.capture/restore`、
  （若是回合内临时状态）确认 `reset_turn_flags` 语义。漏加快照字段的症状是 MC 推演克隆分叉，
  CI 的快照等价性测试与 `MCBridge.validate_replay` 自检会抓。

## 7. 稳定 API 与隐性耦合（最容易被 AI 破坏的地方，逐条注意）

1. **选项 value 字符串是语义键**，启发式 AI（hybrid_bridge.gd `_ai_option`）靠它决策：
   `"official" "custom" "solid" "stem" "keep" "burn" "mutate" "done" "roll" "skip"
   "purify" "demolish" "infect" "solidify" "build"` 及进化 id。**改名 = AI 静默变傻**。
   新增选项请沿用这种短英文键风格。
2. **HybridBridge 还依赖部分 prompt 关键词**：`"额外移动"`、`"失去 1 点生物质"`、`"对方"`。
   改提示文案前先在 hybrid_bridge.gd 里搜一下有没有人依赖。
3. **req 的 tag 值**（`setup_pos` / `move_step` / `attack_target`）与 `actor` 字段是 AI 的场景识别键。
4. **卡牌 / 事件 / 进化的 id**（如 `"excalibur"`、`"doom"`、`"nk"`）贯穿数据表、效果 match、
   能力检查（`has_ability`），全局搜索确认后再改。
5. 同一个 `values` 数组**不要混用 bool 和 int**（Variant 的 `true == 1` 会让线格式下标编码取错）。
6. **对外接口冻结**：`CWGame.new(bridge, n_players, seed)`、`run_setup()`、`run_game()`、
   状态字段名（UI/测试在读）。改名属于破坏性变更，先讨论。
7. `CWData.OFFICIAL_LAYOUT` 与官方癌组织布局对应**实体比赛地图**，除非手册更新，禁止修改。

## 8. 编码规范

- 缩进用 **Tab**（Godot 默认）；文件名 `cw_*.gd`，类名 `class_name CW*`；函数/变量 snake_case。
- 每个文件头用 `##` 写中文职责注释；跨模块公开方法无下划线，模块内私有加 `_` 前缀。
- 面向玩家的日志走 `game.log_line("… %s …" % x)`，中文 + 适当 emoji（参考现有风格）；禁止 print。
- 注释解释"为什么"，不复述代码；与现有中文注释风格保持一致。
- 新脚本的 `.uid` 文件（Godot 自动生成）**必须一起提交**。

## 9. GDScript 踩坑清单（本项目全部实测踩过，AI 尤其容易犯）

1. `:=` 不能从 Variant 表达式推断类型（如未标注返回类型的函数、无类型字典取值）——
   会直接**解析错误**。写 `var x: int = ...` 显式标注。
2. `Resource.duplicate()` 返回 Resource，赋给具体类型要显式标注（如 `var s: StyleBoxFlat = box.duplicate()`）。
3. Variant 比较中 `true == 1` 成立——判类型用 `typeof(x) == TYPE_BOOL`，别用 `Array.has(true)`。
4. **新增 `class_name` 脚本后必须先跑一次导入**（`--import`，见下节），否则无头运行报
   `Identifier "XXX" not declared`。CI 已内置这一步，本地别忘。
5. bash 里管道后取 Godot 退出码用 `${PIPESTATUS[0]}`，`$?` 拿到的是 `tail` 的。
6. 引擎代码里禁用 `randi()/randf()/randomize()/Time.*/OS.*`（破坏确定性，测试会抓）。

## 10. 修改工作流（每次改动必须走完）

```bash
# 1) 改完代码先重新导入（注册新 class_name；<godot> 换成你本机 4.5 console 可执行文件）
<godot> --headless --path game --import

# 2) 跑无头测试：21 个脚本编译 + 6 局完整对局 + 确定性/线格式回归，必须 ALL TESTS PASSED
<godot> --headless --path game -s tests/headless_test.gd

# 3) UI 改动还需真开窗口人工过一遍（菜单 → 人机对战开一局走几个回合）
<godot> --path game
```

- 提交信息用中文，说清"改了什么 + 为什么"；一次提交只做一件事。
- **推送前先 `git pull --rebase`**（队友会直接往 main 推东西，包括 docs/obsidian 笔记）。
- CI（GitHub Actions）在 Linux 上用 Godot 4.5 stable 复跑同一套测试，红了立即修，别绕过。
- 修 bug 优先先在 `tests/headless_test.gd` 里补一个能复现的检查，再修到绿。

## 11. 常见任务菜谱（照着做，别自创路径）

**加/改一张卡牌**：`cw_data.gd` 的 `CARDS_IMMUNE/CARDS_CANCER` 定义（id/名称/文案/张数/kind）→
即时牌在 `cw_cards.gd::_apply_card` 加 match 分支；能力牌在使用点用 `p.has_ability("id")` 检查
（参考 `chemotaxis`、`doom`）。注意保持阵营牌总数与手册一致（各 28）。

**加/改一个世界事件**：`cw_data.gd::WORLD_EVENTS`（含 `side`/`limited` 标记）→
`cw_events.gd::apply` 加分支。回合级增益用 `game.flag_*`（记得在 `cw_world.gd::round_start`
清理），永久增益用 `game.perm_*`——**两者都要加进 `state_hash()`**。

**加/改进化能力**：`cw_data.gd::EVOS_*` → 效果分散在使用点（搜现有 evo id 如 `"nk"`、`"blood"`
看模式）。改完全局搜该 id 确认所有触点。

**调数值平衡**：只动 `cw_data.gd` 顶部常量与各表；逻辑文件不用碰。

**改 AI 强度/行为**：启发式策略动 `hybrid_bridge.gd`；蒙特卡洛搜索的参数/评分动
`mc_bridge.gd`（旋钮与原理见 `docs/AI设计.md`，改完跑 `tests/mc_benchmark.gd` 看胜率）。
桥是"答案生成侧"，不受确定性红线约束，但注意第 7 节的语义键耦合，
且推演克隆绝不能触碰真实对局的 `game.rng`。

**改 UI 布局/样式**（位置、间距、字体、配色、文案）：在 Godot 编辑器里改 `scenes/*.tscn`
与 `scenes/ui_theme.tres`，不用碰脚本；改节点名前先搜脚本里的 `%节点名` 引用。

**改 UI 交互/逻辑**：动 `scripts/ui/`；需要引擎新信息时优先读现有状态，其次给 req 加字段
（加在 `cw_game.gd` 的 ask_* 处，并更新 `cw_bridge.gd` 的格式文档）。

**改既有规则的解释**：先查 `docs/规则电子化说明.md` 是否已有裁决；要推翻必须同步更新该文档
对应条目（写明新裁决与理由），再改代码。

## 12. AI 禁止清单（负面约束，出现即回退）

- ❌ 未被要求的重构、重命名、格式化、"顺手优化"——每行改动都应能对应到当次任务
- ❌ 给 core 挂场景节点 / 在 core 里引用 UI / 绕过桥直接造答案
- ❌ 引入第三方插件、Autoload 单例、C# —— 本项目零外部依赖，保持
- ❌ 改 `.godot/` 目录内容（已 gitignore）、手改 `.uid` 内容
- ❌ 用 Godot 4.5 以外的版本开发或让文档/CI 版本漂移
- ❌ 删除或改写 `docs/规则电子化说明.md`、`docs/联机设计.md` 的既有裁决（只可追加/讨论后修订）
- ❌ 跳过测试直接推 main；测试红了靠改测试变绿（除非测试本身错，需说明理由）

## 13. 协作约定

- 动手前在群里说一声要改哪个模块，避免两个人（的 AI）同时改同一文件产生合并地狱。
- 大型改动（新模式、引擎结构调整、新请求类型）：先发设计到 docs/ 或群里讨论，达成一致再写码。
- 本文档本身的修订也走讨论——它是所有 AI 的"宪法"，随意改动会让协作失去基准。
