# 联机设计（预留接口说明）

> 状态：**接口已预留，网络层未实现**。本文档描述联机的技术路线、当前代码里已经准备好的接口，
> 以及团队手改规则模块时**必须遵守的确定性守则**（违反会导致联机失步）。

## 一、技术路线：确定性锁步（Deterministic Lockstep）

回合制棋盘游戏的标准联机做法。**不同步棋盘状态，只同步"决策"**：

1. 房主创建房间，分配座位（哪位真人控制哪枚细胞），确定随机种子 `seed`，广播给所有客户端；
2. 每个客户端用同一 `seed` 本地跑一份完整规则引擎（`CWGame`）；
3. 引擎的一切随机（掷骰、洗牌、世界事件抽取）都出自 `game.rng`——种子相同、调用顺序相同，
   每端骰出的点数天然一致，**骰点不需要上网络**；
4. 引擎每次 `bridge.ask(req)` 是一个严格串行的决策点：轮到谁（`req.owner_id / owner_faction`），
   谁的客户端把答案（线格式）发给房主，房主转发给所有端，各端喂给本地引擎；
5. 每个世界回合结束时各端比对 `game.state_hash()`，不一致立即发现失步；
6. 断线重连 / 中途加入 = `seed` + 从头的答案日志快速重放（引擎在无 UI 时瞬时解析，
   现有无头测试就是这么跑完整局的）。同一机制免费带来**对局回放/复盘**功能。

网络层建议用 Godot 自带的 High-Level Multiplayer（`ENetMultiplayerPeer` + RPC），
局域网直连或一台做主机即可，不需要专用服务器。

## 二、当前已预留的接口

| 接口 | 位置 | 说明 |
|---|---|---|
| 决策归属字段 | `cw_game.gd` 的 `ask_option / ask_hex / ask_edge` | 每个请求自动带 `owner_id`（玩家 id，阵营级决策为 -1）与 `owner_faction`。`who` 仍是显示字符串。未来 NetBridge 按 owner 路由"该谁答"；HybridBridge 已改用它区分人类/AI |
| 答案线格式 codec | `cw_bridge.gd` 的 `encode_answer / decode_answer`（static） | 把答案转成可网络序列化的 Variant：选项→下标 int、格子→Vector2i、边→String、取消→null。选项答案可能是对象引用（如 CWPlayer），必须经此转换才能上网络 |
| 局面摘要 | `cw_game.gd` 的 `state_hash()` | 棋盘+玩家+牌库+标记压成一个 int，用于失步检测 |
| 确定性回归测试 | `tests/headless_test.gd` 的 `_test_determinism` | 同种子跑 3 局（普通×2 + 全程 codec 往返×1），断言 `state_hash` 一致。**CI 每次提交都会跑**，守护锁步依赖的确定性 |

## 三、未来 NetBridge 的工作清单（实现联机时再做）

新建 `scripts/net/net_bridge.gd extends CWBridge`，大致形状：

```gdscript
func ask(req):
    if _local_seats.has(req.owner_id):        # 本端玩家 → 走 UI（复用 UIBridge 逻辑）
        main.show_request(req)
        var v = await answered
        rpc("relay_answer", CWBridge.encode_answer(req, v))
        return v
    else:                                     # 远端玩家 → 等网络包
        var wire = await _remote_answer_received
        return CWBridge.decode_answer(req, wire)
```

另需：大厅/建房 UI、座位分配、`state_hash` 定期比对、答案日志与重放。
阵营级决策（`owner_id == -1`，如布置阶段、双重打击选人）由该阵营的某个约定座位作答
（建议：该阵营行动顺序最靠前的存活玩家），实现时在 NetBridge 统一映射。

## 四、⚠️ 修改规则模块的确定性守则（红线）

联机上线后，任何破坏确定性的改动都会导致各端棋盘悄悄分叉。手改
`cw_setup / cw_world / cw_events / cw_turn / cw_movement / cw_combat / cw_cards` 时务必遵守：

1. **引擎内随机只准用 `game.rng`**。禁止 `randi()`、`randf()`、`randomize()`、
   `Time.*`、`OS.*`——这些每端结果不同。（桥/AI 里的随机不受限，那是"答案生成"，不进引擎。）
2. **一切玩家决策必须走 `game.ask_option / ask_hex / ask_edge`**，who 传玩家对象或
   `CWData.FACTION_*` 常量，不要自造请求或绕过桥直接读输入。
3. **新增影响规则的状态时，把它加进 `CWGame.state_hash()`**（函数注释处有提醒）。
4. **不要让引擎读 UI/窗口/操作系统状态**。引擎只能依赖：自身状态 + `game.rng` + ask 答案。
5. pick_option 的同一个 `values` 数组里**不要混用 bool 和 int**（Variant 相等判断 `true == 1`
   会让下标编码取错项）。

改完跑一遍无头测试（先 `--import`），`_test_determinism` 会自动帮你把关。
